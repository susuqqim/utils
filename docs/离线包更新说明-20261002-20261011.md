# WorkBuddy2API 更新说明（2026-10-02 → 2026-10-11）

本版二进制内报版本：**1.11.7-panel**（`/panel/api/overview` 可查）。安装方式见文末。

## 一、重要行为变化（建议先读）

1. **网关侧隐藏"有名无服务"的模型**（新配置 `hidden_models`）
   - 背景：上游目录长期保留一批**没有服务**的模型名（直接请求得上游原文
     `http 400 {"code":11102,"msg":"model [glm-4.7] service info not found"}`）。历史用量显示这些模型
     在本网关**从未产出过一个 token**，但目录照旧列出它们 ⇒ 客户端枚举后逐个尝试 ⇒ 每次写入
     6h→12h→24h 的**模型级负缓存**，面板一片"预计 X 后重试"，还掩盖真正的临时限流。
   - 现在：`hidden_models: ["glm-4.6", …]`（顶层配置，默认空=不改行为）⇒ `/v1/models` **不再列出**；
     直接请求**本地 400 `model_hidden`**（**不打上游、不计费、不写冷却**）。
   - 本包建议名单：`glm-4.6 / glm-4.6v / glm-4.7 / glm-5.0 / hy4-preview-x / kimi-k2-thinking / minimax-m2.5`。
2. **请求体上限**：`server.max_body_mb` 默认 **8**，建议 **64**（`{"server":{"max_body_mb":64}}`）。
   超限时服务端回 **413**，但客户端常表现为**连接重置**（因上传中被拒并关连接）。
3. **面板文案**：上游 11102 一类不再写"预计 X 后重试"，改为
   **「上游无此模型服务（换模型才有用）」**（title 里说明"不是限流、等待无用、建议换模型或 `global:<id>`"）。

## 二、修复（本周期）

- **reqlog**：请求体 >64KB 时被截断（`io.MultiReader` 修复，200KB 用例守护）；`since` 非法或未启用
  归档时**不再静默退回内存环**，而是回 `since_error` + 回显生效 `limit`。
- **路由/冷却**：上游 11102 的 `Until` 判定、软限流 `AuditOnly` 升级口径、`no available channel`
  过度归类（会误伤正常模型）等已按实测收敛。
- **反探测**：`11‑128`（U+2011 连字符）门此前因字形差异**实际失效**，已修实现与测试字面量并加守护。
- **探测 UA**：`probeV3` 此前把 UA 判反，已改为按账号默认 UA 构造。
- **面板保存**：`credit_floor` 误入 JS 时长字段黑名单会**导致面板保存全部失败**，已移除 + 守护用例。
- **11148 形状**（背靠背并行工具调用）：新增**合帧**处理，此前会被逐帧误判为业务错误。
- **用量账本**：分域（cn/global）桶键 + 前缀缓存命中口径修正（面板两个 KPI 此前偏低）。

## 三、本轮实测结论（供排障参考）

| 项 | 结论 |
|---|---|
上下文上限 | `deepseek-v4.1-flash` = **1,048,576 tokens**；超限 → **400 `prompt_too_long`**（内嵌上游 `11115`），**不计费、不罚号** |
体量超限 | `max_body_mb` 超限 → **413**（客户端常见连接重置） |
模型不可用 | `400/503`，语义化错误码（`model_unavailable` / `no_healthy_account` / `model_hidden`） |
前缀缓存 | 前缀递增请求实测命中（8.9 万 / 35.5 万 tokens 全命中）⇒ 面板命中率可信 |

## 四、安装与升级

- **Windows**：`workbuddy2api-1.11.7-x64.msi`（当前用户级安装）；脚本方式见 `install.ps1`。
- **原生单文件**：`wb2api-windows-amd64.exe` / `wb2api-linux-{amd64,arm64}` / `wb2api-darwin-{amd64,arm64}`。
- **离线整包**：`workbuddy2api-offline.tar`（含源码与构建脚本，可离线重建）。
- **升级前请备份**：`%LOCALAPPDATA%\workbuddy2api\wb2api-core.exe` 与 `%USERPROFILE%\.workbuddy2api\config.json`；
  替换二进制后先看 `/healthz` 与 `/v1/models` 再放量。本机提供的 `upgrade-with-rollback.ps1` 会在
  启动后 60 秒内健康检查失败时**自动还原旧二进制与配置并重启**。
- 校验：各产物附 `SHA256SUMS`（MSI 与二进制同源，Windows 二进制 hash 见该文件）。


## 六、本版（批次35–44，含生产已验证项）

1. **缓存命中修复（重要）**：`prompt_cache_key` 在客户端**不带 conversation id** 时回退到**会话 key** ——
   否则它会退化成"每账号一个常量"，同账号多客户端共用一个前缀缓存槽并互相驱逐，表现为"**缓存命中率下降**"。
   生产实测（两会话交替）：命中 **99.7%**，单次费用 **0.92 → 0.02 credits**。
2. **空 `function.name` 的 tool_call 一律剔除**（上游会判 `11133 model_param_invalid` ⇒ 503）。
3. **DSML 原生工具调用标记**（模型把工具调用吐成正文标记）：新增解析器 + 流式/非流式接线；未声明 tools 时
   **逐字节零改写**，思维链不动，收尾保证 `finish_reason=tool_calls` 唯一且在调用帧之后。
4. **安全修复（对抗审计）**：解析器缓冲加上界（`maxMarkupHold=64KB`，超限放弃修复并原文透出）——
   此前内存会随响应流线性增长；并修正放弃路径**丢 24 字节**的副作用。
5. 对齐项：`logfmt.ShortUA`、`auth.IsEnterprise`，以及上游 credit_floor 等测试的吸纳。

## 五、防杀软误报提示

第三方杀软可能对本包二进制**误报**（Windows Defender 已关闭时可忽略其记录）。建议把构建目录与
运行目录（`%LOCALAPPDATA%\workbuddy2api\`）加入信任列表，并以上面的 `SHA256SUMS` 校验后再放行。
